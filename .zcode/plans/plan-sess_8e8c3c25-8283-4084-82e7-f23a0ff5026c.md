# 让 ZCode 接入 CodeBuddy-API-Proxy（chat 路径净化 + ZCode 品牌词替换）

## 实证结论（本次排查关键发现）
- 日志证实你已配置过 ZCode → 本代理（`baseURL: http://127.0.0.1:3800/v1`，`openai-compatible`，模型 `hy3`）：真实会话请求（`main_turn`/`compact`）被上游以 `code:11128 Illegal API invocation from an unapproved channel` 拒绝（400），而 ZCode 内置模型测试能过——因为测试请求不带完整系统提示词。
- 对 ZCode 实际发送的系统提示词做逐词排查：**Codex / OpenAI / Claude / Anthropic / Gemini / Cursor 等出现次数全为 0，唯一命中拦截的品牌词是 `ZCode` 本身**。即 CodeBuddy 拦截词表包含 "ZCode"，必须对它做替换，否则净化了对 ZCode 无效。
- 请求头无需改动：`core/openai.js:136` 构造上游头时从零建（`buildAuthHeaders`），ZCode 的 UA 等不透传；`Authorization: Bearer` 与 `verifyClientKey`（`core/auth.js:270`）兼容。

## 改动内容

### 1. 新增 `core/sanitize.js`（共享净化模块）
```js
const RULES = [
  [/Codex/gi, 'CodeBuddy'],
  [/OpenAI/gi, 'Tencent'],
  [/Claude/gi, 'CodeBuddy'],
  [/Anthropic/gi, 'Tencent'],
  // ZCode 在路径中出现频繁（.zcode、\zcode\、zcode-plugins 等），
  // 用负向断言排除路径/标识符场景，只替换独立出现的品牌词
  [/(?<![\w.\-\/\\])ZCode/gi, 'CodeBuddy'],
];
```
注释说明：再遇 11128 时用 `CODEBUDDY_DEBUG` 的 dump 定位剩余触发词后在此追加；含路径形态的词必须用负向断言。导出：
- `sanitizeText(s)`：跑全部规则（原 `sanitizeForBackend` 行为）。
- `sanitizeChatPayload(payload)`：只处理 `messages[]` 中 `role` 为 `system`/`developer` 的 `content`（兼容字符串与 `{type:'text',text}` 数组）及 `tools[].function.description`；用户/assistant 消息、tool_calls 参数、工具名一律不动（沿用现有策略，工具名改动会破坏 tool_call 往返）。

### 2. `core/openai.js`：chat 路径接入净化（本次修复的核心）
- `handleProxy` 中模型名处理后、`JSON.stringify(payload)`（约 105 行）前：`upstreamPath === '/v2/chat/completions'` 时调用 `sanitize.sanitizeChatPayload(payload)`。
- `/v1/completions`、`/v1/embeddings` 不处理。
- `CODEBUDDY_DEBUG` 开启时，对称于 `responses.js:397`，把净化前后载荷 dump 到 `/tmp/codebuddy-debug-last-chat.json`。

### 3. `core/responses.js`：改用共享模块
- 删除本地 `sanitizeForBackend`（19-22 行），`require('./sanitize')` 用 `sanitizeText`，三处调用点行为不变。

### 4. `README.md`
- 更新净化说明（约 167 行）：补充「ZCode 也在拦截词表内（实测 11128），代理会把独立出现的 `ZCode` 替换为 `CodeBuddy`，`.zcode` 等路径不受影响」，并说明 `/v1/chat/completions` 现已净化。
- 新增「接 ZCode CLI」一节：`~/.zcode/v2/config.json` 新增 `"codebuddy": { "kind": "openai-compatible", "options": { "baseURL": "http://127.0.0.1:3800/v1", "apiKey": "<密钥或 dummy>" } }`；强调 baseURL 以 `/v1` 结尾（AI SDK 自动拼 `/chat/completions`）；模型填目录内模型或自定义名；重启 ZCode 选择该 provider。
- 提示：若更换其他客户端后仍遇 11128，开 `CODEBUDDY_DEBUG` 看 dump 定位新触发词。

### 5. `package.json`
- `test` 脚本 `node --check` 列表加 `core/sanitize.js`。

## 不做的事
- 不新增 `/v1/messages` Anthropic 端点；不做管理页可配置规则、不动 web 前端。
- 不净化用户消息 / 工具参数 / 工具名（保持文档化策略）。

## 验证
1. `npm test` 通过。
2. `node -e` 断言：`sanitizeText('You are ZCode. See C:\\u\\.zcode\\cli and zcodejwttoken')` → `You are CodeBuddy. See C:\u\.zcode\cli and zcodejwttoken`（路径/标识符不动）；`sanitizeChatPayload` 只改 system/developer 与工具描述，user 消息与 tool_calls 原样。
3. `npm start` 后 curl `/v1/chat/completions`，system 消息含 "You are ZCode, an interactive coding agent"，确认不再 11128（或 debug dump 显示已净化为 CodeBuddy）。
4. 你在 ZCode 重新加上 codebuddy provider（README 模板）实测一轮真实对话——之前 `hy3` 会话的失败模式应消失；若仍 11128，用 dump 定位下一个触发词再补规则。
